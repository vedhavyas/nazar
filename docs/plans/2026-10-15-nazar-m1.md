# Nazar M1 - Server + Web on the Hub, One Camera Live in the Browser

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Docker image (Rust server + Svelte web + go2rtc) deployed to the hub; log in with a phone OTP; one camera plays live in the browser over WebRTC through the hub's coturn.

**Architecture:** `nazar-server` (Rust, axum) owns the Qubo session, mints camera streams on a loop, feeds them to a bundled `go2rtc` (which transcodes and serves WebRTC), and serves the built Svelte SPA from the same binary. The browser is a plain client of the server: HTTP + one go2rtc-proxied WebRTC path. Deployed as a single container via the hub's docker-compose convention.

**Tech Stack:** Rust (axum, tokio, reqwest, rumqttc later, serde), Svelte 5 + Vite (WebRTC via go2rtc's `video-rtc.js`), go2rtc (bundled binary), ffmpeg (in image), Docker multi-stage, GHCR, hub-modules compose.

**Spec:** `docs/design.md` (sections 2-5 are M1's contract). Reference research: `docs/qubo-api-spec.md` (auth §3.3, streaming §6, MQTT §5), the Python reference implementation at `/Users/vedhavyas/Projects/qubo-spike/venv/lib/python3.14/site-packages/qubopy/` and the spike's proven `mint.sh` + `go2rtc.yaml` at `/Users/vedhavyas/Projects/qubo-spike/`.

## Review Focus

Inputs/conditions the spec implies but this milestone's happy path may not exercise - each gets its test in the owning task:

1. **OTP failures** (wrong code, expired code, rate limit `ERR_SM_057`): the login screen must show the real reason and a retry path, never a dead end - Task 3.
2. **Session expiry mid-view** (access tokens die at 3600s, no refresh on the OTP path): the stream loop must re-mint without killing the page - Task 6.
3. **Mint failures / camera offline** (`p2pStreaming` refusing, mint 5xx): the tile shows a truthful offline state and keeps retrying - Task 6.
4. **WebRTC negotiation failure** (client cannot reach coturn/ICE): the page must surface a legible error instead of a black rectangle - Task 8.
5. **Hub/network down**: the SPA must show "server unreachable" (the API client's health check) rather than hanging - Task 7.
